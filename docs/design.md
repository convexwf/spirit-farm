# Spirit Farm 核心设定（v0.1）

> 本文件是项目的设计"宪法"。所有玩法决策先在这里对齐，再写代码；
> 任何改动都要同步更新本文件。v0.1 只锁定基础设定，数值全部待验证。

## 1. 一句话定位

一个类星露谷的农场经营游戏，但所有重复农活都可以交给**精灵**代办；
精灵不是买来的宠物，而是**用作物种出来的**，并且靠吃作物成长、进化、变强。
在灾灵入侵时，精灵还要负责守护农场。

## 2. 核心循环

```text
种田 → 收获作物
         │
         ├── 卖出换钱 → 扩建农场 / 解锁新作物
         └── 喂养精灵 → 精灵升级 / 进化 / 能力增强
                            │
                            ├── 代办农活 → 玩家腾出时间 → 种更多田
                            └── 守护农场（战斗）→ 掉落灵肥 → 田地产出与结灵率提升

特定条件下收获"结灵" → 孕育新精灵 → 精灵数量增加 → 可代办的活更多
```

关键点：**同一份作物同时是商品、食物、进化素材和孕育媒介**。玩家每次
收获都要做资源分配决策，而不是"多收多卖"一条路走到底。

战斗不是独立玩法：精灵的战力来自喂养，战斗奖励（灵肥）反哺种植，
整条循环仍然以作物为燃料。

## 3. 设计支柱

### 3.1 代办是有成本的自动化

- 精灵干活要消耗能量，能量靠吃作物恢复 → 自动化不是免费的，它的燃料是
  持续的种田产出；
- 精灵有工作上限（一天能干的活有限）→ 不会变成纯挂机；
- 早期精灵效率低于玩家，升级后逐步超过 → 自动化是**养成的奖励**，
  不是开局默认状态。

### 3.2 作物即养成资源

- 每类作物都有"精灵亲和属性"：元素、喂养经验、心情加成、进化素材；
- 不同作物养出不同方向的精灵 → 收集和种植多样性有了理由；
- 喂养不是无脑加经验：有的作物升经验快，有的作物加心情，有的作物强化
  特定能力，玩家按想养的精灵类型搭配食谱。

### 3.3 孕育是收获的延伸

- 精灵不是从商店买的，而是收获时以一定概率"结灵"获得；
- 结灵概率受收获品质和照料度影响 → 高品质种植本身成为培育精灵的前提；
- 不同作物孕育不同精灵种类 → "想养水系精灵？去种莲子/水芹"，
  目标感直接落到种田上。

## 4. 精灵生命周期

```text
结灵（收获时概率触发）→ 灵蛋/灵苗 → 幼体 → 成体 → 进化（分支）
                                                    │
                                        ← 不同喂法走向不同分支
```

### 4.1 结灵（诞生，与作物强绑定）

- 触发：作物成熟收获时，按 `品质 × 照料度` 结算基础概率；
- 产物：灵蛋（或灵苗），需要玩家"孵化"：喂指定作物 + 等待若干天；
- 种类：由作物决定（`CropData.spirit_species` 权重抽取）；
- 幼体初始数值由收获品质决定（高品质 → 更高初始属性）。

### 4.2 喂养与成长

- 精灵属性：等级、经验、能量、心情（信任）、元素、技能；
- 喂养消耗作物，不同作物给不同成长（经验 / 心情 / 能力加成）；
- 能量耗尽精灵拒绝干活，心情过低会罢工或消极怠工；
- 心情通过喂偏好食物、陪玩、完成孵化仪式提升。

### 4.3 进化

- 条件：等级达标 + 累计喂足指定作物 + 心情阈值；
- 进化是**分支选择**（喂火系方向还是草系方向），不是一条直线；
- 进化改变形态（换贴图）+ 解锁/强化技能 + 提升数值上限；
- 进化方向应该在前期就可见（图鉴里显示分支），让玩家有明确养成目标。

## 5. 代办系统

### 5.1 工作类型

| 工作 | 对应农活 | 擅长元素示例 |
| --- | --- | --- |
| 浇水 | 每日浇水 | 水 |
| 锄地/播种 | 开垦、下种 | 土 |
| 收割 | 成熟收获 | 风 |
| 采集 | 野外的可采集物 | 草 |
| 伐木/采矿 | 资源收集 | 木/岩 |
| 烹饪 | 作物加工（远期） | 火 |

初期只做前三种，验证循环；采集、伐木、采矿、烹饪逐个追加。

### 5.2 分配与执行

- 玩家通过"精灵面板"或把精灵带到田边来分配工作；
- 每只精灵同时只能干一件事，按地块/区域批量执行；
- 干活消耗能量，效率由 `work_speed` 和等级决定；
- 完成后触发 `chore_completed` 事件，回写农场状态。

## 6. 战斗与守护（方向已纳入主线，具体规则待验证）

### 6.1 世界观钩子：灾灵与地脉裂缝

- 夜晚会有"灾灵"顺着地脉裂缝爬进农场，啃食作物、污染田地；
- 战斗的目的不是刷怪升级，而是**守护作物**——失败的代价是作物被啃、
  精灵疲惫，而不是抽象的掉血；
- 地脉裂缝本身可以用作物修复（种"结界草"堵住裂缝），防御也是种出来的。

### 6.2 战斗形式

| 形式 | 特点 | 结论 |
| --- | --- | --- |
| 回合制（宝可梦式） | 好实现、好平衡、UI 清楚，和种田节奏一致 | **v1 采用** |
| 半自动 | 玩家选技能、精灵执行，玩家不做操作考试 | v1 的交互方式 |
| 实时战斗（矿洞式） | 手感强，但需要寻路、动画、输入 | 远期备选，先不做 |

v1 战斗小样：1 只精灵 vs 1 只灾灵，先用 Tiny Battle 素材单独验证
手感与循环，验证通过后再接入主线。

### 6.3 作物驱动的战斗机制

- **技能是喂出来的**：喂辣椒学"爆裂"、喂薄荷学"加速"、喂向日葵学
  "光盾"——种植即配招；
- **战前料理**：作物组合做战前餐，给临时 buff，烹饪直接服务战斗；
- **元素克制简化**：火 > 草 > 水 > 火，土/风/光/暗再来一圈；克制关系
  印在作物属性上，玩家种田时自然记住；
- **进化改变战斗形态**：进化换技能池、数值曲线和可习得技能，
  喂哪个进化方向直接决定打法；
- **羁绊技**：心情满 + 持有特定作物 → 玩家与精灵合体技，
  把羁绊做成战斗亮点。

### 6.4 战斗反哺种田

- 战斗掉落**灵肥/灵尘**：施到田里提升作物品质和结灵概率；
- 玩家不直接下场，主力是精灵；玩家只能做有限辅助（扔料理、鼓舞），
  避免战斗系统跑偏成动作游戏。

## 7. 扩展创意池（未锁定，进入 MVP 前需要再对齐）

| 创意 | 内容 | 状态 |
| --- | --- | --- |
| 灵屋/祭坛 | 用作物建材扩建，给精灵"灵位"，装饰影响心情和产出 | 远期候选 |
| 谱系繁殖 | 两只精灵好感达标 + 种出"姻缘作物" → 混血新精灵 | 远期候选 |
| 季节限定灵 | 夏夜萤火灵、秋日丰收灵、冬雪灵，与季节作物互相咬合 | 远期候选 |
| 月相与节日 | 满月夜结灵率提升；节日献祭作物换稀有精灵 | 远期候选 |
| 心情行为化 | 心情低 → 偷懒、战斗失误、跑去看风景，用偏好食物哄回 | 建议 v0.3 起按行为实现，不做纯数值 |
| 玩家羁绊 | 好感高解锁"听懂精灵话"、短暂借用精灵能力 | 远期候选 |

## 8. 平衡与体验原则

1. **自动化是成长奖励**：低级精灵效率低于玩家，别让开局就挂机；
2. **不做纯滚雪球**：精灵数量、单只精灵工作上限、进化分支都有约束，
   玩家永远需要做取舍（喂哪只、进化哪个方向、卖还是留）；
3. **精灵有情绪**：心情影响行为和动画，避免精灵变成"会动的工具"；
4. **结灵是稀有事件**：初期低概率，玩家第一次"种出精灵"应该是
   有仪式感的惊喜时刻；
5. **数字克制**：所有数值先在文档里定义区间，不边做边拍脑袋。
6. **战斗必须反哺种田**：战斗奖励（灵肥）回到田地产出，避免"种田游戏"
   和"战斗游戏"割裂成两个游戏；
7. **战斗难度跟随养成**：战力主要来自精灵培育而非玩家操作，
   操作只做辅助决策。

## 9. 技术契约（一开始就定死）

### 9.1 数据驱动

- `CropData`（Resource）：生长阶段、季节、售价、结灵概率、
  精灵亲和（元素 / 喂养效果 / 孕育种类 / 是否进化素材）；
- `SpiritData`（Resource）：种类、元素、基础数值、成长曲线、
  偏好食物、技能列表；战斗字段（HP/攻击/防御/速度、可习得技能）；
- 进化分支：`EvolutionData`（前置种 + 等级 + 条件 → 后置种）；
- `SkillData`（Resource）：技能、元素、威力、命中、习得条件（喂食作物）；
- `BattleEncounterData`（Resource）：灾灵编组、难度、掉落（灵肥）。

新作物、新精灵、新进化都只加 `.tres`，不改代码。

### 9.2 事件总线（EventBus）

核心事件从第一天就存在，模块间只通过信号通信：

```text
crop_planted / crop_harvested / crop_matured
spirit_born / spirit_fed / spirit_leveled_up / spirit_evolved
spirit_mood_changed / chore_assigned / chore_completed
battle_started / battle_won / battle_lost / spirit_used_skill
```

### 9.3 存档

必须持久化：精灵列表（种类、等级、经验、心情、能量）、进化状态、
当前分配的工作、精灵队伍、已习得技能、图鉴进度、灵肥库存、作物亲和
数值版本号。存档 schema 从 v0.1 就带上精灵字段，避免后续迁移。

## 10. MVP 分期

| 版本 | 内容 | 验证目标 |
| --- | --- | --- |
| v0.1 | 地图 + 移动 + 时间系统 + 农场闭环（锄/种/浇/收）+ 基础背包 | 玩家能种田赚钱 |
| v0.2 | 1 只精灵：喂食升级 + 代办浇水；收获结灵（孵化） | 核心循环"种 → 喂 → 代办"跑通 |
| v0.3 | 多精灵 + 多种代办（锄地/播种/收割）+ 心情系统 | 自动化有成本、有取舍 |
| v0.4 | 战斗小样：回合制 1v1（精灵 vs 灾灵）+ 技能喂食解锁 | 战斗与种田闭环（掉落灵肥） |
| v0.5 | 进化分支 + 能力增强 + 图鉴 | 养成深度 |
| 远期 | 采集、伐木、采矿、烹饪、NPC、季节事件、节日、灵屋、谱系繁殖、季节限定灵 | 完整游戏感 |

战斗小样建议单独验证手感后再接入主线；v0.4 之前不引入 Tiny Battle
之外的战斗素材。

## 11. 待定问题（开放，不影响 v0.1-v0.2 开工）

- 战斗：已定方向为守护农场的回合制；**矿洞探险**是否做仍待定；
- 灾灵只出现在夜晚，还是特定季节/天气更频繁？（倾向：初期只在夜晚）
- 战斗失败的具体惩罚？（倾向：作物被啃 + 精灵心情下降，不回滚已消耗）
- 玩家在战斗中的参与度？（倾向：不直接下场，只做辅助决策）
- 谱系繁殖、灵屋是否进入主线？（创意池，未锁定）
- 进化是分支树还是网状？（先按分支树做，数据结构兼容网状）
- 精灵数量上限？（建议后期再做，v0.2 先做单只）
- 孵化期玩家要不要持续照料？（倾向：要，强化"孕育"的仪式感）
- 精灵要不要有名字、个性、对话？（倾向：有名字和简单好感对话）
